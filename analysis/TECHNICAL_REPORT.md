# VW-MENU Technical Analysis Report
*Read-only analysis — no files modified during investigation*

## 1. Project Overview

**Purpose**: A standalone Roblox UI/aim-assist & ESP system that runs entirely client-side via a LocalScript. No HTTP, no external libraries, no RemoteEvents, and no persistent server-side state.

**Primary entry points**:
- `src/v2/main.lua` – the v2 bootstrapping that builds a `ScreenGui` named `VWMenuRuntime_v2`, creates the modular subsystems (`config`, `aim`, `esp`, `ui`, `tracker`) and returns the `app` table.
- `dist/VW-MENU.lua` – a bundled, single‑file version generated by `tools/build-v2.mjs`. It can be copied into a LocalScript directly.
- `loader.lua` – optional raw‑loader that fetches the bundled script via HTTP and executes it with `loadstring` (intended only for a test host that permits HTTP and `loadstring`).

**File structure** (33 files total):
- 7 v2 modules under `src/v2/`: config, cleanup, tracker, aim, esp, ui, main
- 7 v1 preserved modules under `src/`: Main, UIController, FeatureRegistry, FeatureController, SettingsManager, NotificationManager, CleanupManager
- Tests: core.spec.luau, controllers.spec.luau, signal.luau
- Build/verification tools: build-v2.mjs, verify-v2.mjs
- Documentation: README.md, IMPLEMENTATION_PLAN.md, DESIGN.md, V2_ANALYSIS.md, V2_TESTS.md
- Analysis: FUNCTION_INVENTORY.md, REA_REPORT.md

## 2. High‑Level Architecture (v2)

```
Bootstrap (src/Bootstrap.client.lua)
    └─ Main (src/v2/main.lua)
        ├─ Config            – runtime configuration, defaults, validation, publish/subscribe
        ├─ Tracker           – tracks all Players, their characters, Humanoids, parts, and emits change events
        ├─ AimController     – client‑side aim assist, renders FOV circle (Drawing or ScreenGui), bind‑to‑RenderStep
        ├─ ESPController     – creates overlays (Highlight, BoxHandleAdornment, BillboardGui) per tracked player
        ├─ UI (src/v2/ui.lua) – native UI controller (tabs, toggles, sliders, dropdowns, color picker, status)
        └─ Cleanup (src/v2/cleanup.lua) – hierarchical cleanup manager (connections, instances, scopes)
```

**Supporting modules (v1 path under `src/`)**:
- `FeatureRegistry.lua` – defines tabs and feature definitions.
- `FeatureController.lua` – owns per‑feature state, applies changes, runs button callbacks.
- `SettingsManager.lua` – client‑session persistent settings stored as a Folder under the Player.
- `NotificationManager.lua` – toast‑style notifications.
- `CleanupManager.lua` – generic LIFO cleanup for v1 code.

**All modules are pure Lua (Luau) ModuleScripts**; they never use `_G`, `CoreGui`, or server‑side services.

### Module Relationships

- `Bootstrap.client.lua → src/Main.lua` (v1) or `src/v2/main.lua` (v2) depending on which version you copy.
- `Main.lua` pulls in UIController, FeatureRegistry, FeatureController, SettingsManager, NotificationManager, CleanupManager.
- `src/v2/main.lua` composes the v2 subsystems (`Config`, `Tracker`, `Aim`, `ESP`, `UI`) and wires them together.
- All UI components (`ui.lua`) expose `AddTab`, `AddToggle`, `AddSlider`, `AddButton`, `AddDropdown`, `AddColor`, `AddStatus` – used by `src/v2/main.lua` to build the menu.
- `Config` notifies listeners; UI widgets subscribe to keep UI in sync.
- `Tracker` emits changes; ESP subscribes to create / update overlays.
- `Cleanup` provides scoped disposal for each subsystem (e.g., per‑player overlay scope, render‑step scope).

## 4. Module Deep Dive

### 4.1 Config (`src/v2/config.lua`)

**Purpose**: Runtime configuration with defaults, validation, ranges, and publish/subscribe.

**Key features**:
- 21 defaults including AimEnabled, SmoothSpeed (6), FOVRadius (100), ShowFOV, WallCheck, TeamCheck, TargetLock, TargetPart (Head), ESPEnabled, ShowHealth, ShowDistance, TeamColors, ShowTeammates, FriendColor (#42ADFF), EnemyColor (#FF4D5A), HighlightTransparency (0.65), FOVColor (#42ADFF), FOVThickness (1.5), FOVTransparency (0.4), NameColor (#E7F1FA), BoxColor (#42ADFF), HighlightColor (#42ADFF), NameColorMode/BoxColorMode/HighlightColorMode (Team / Relation / Custom), ReducedMotion (false).
- Type validation: rejects NaN, infinite, wrong types, invalid choices, invalid hex format (#RRGGBB).
- Range clamping with step granularity (e.g., SmoothSpeed 1‑30, FOVRadius 30‑400).
- Choice validation for TargetPart, color modes.
- Hex normalization: `#abc123` → `#ABC123`.
- Subscribe pattern: listeners notified on every `Set` change; can unsubscribe.
- Reset: restores all values to defaults; does not share state between instances.
- Idempotent `Destroy`: clears listeners.

**Test results** (core.spec.luau): 10/10 tests passed — defaults/limits, invalid rejection, hex normalization, observer pattern, cleanup idempotency, scope discard, FPS‑independent alpha, FOV screen distance, sameTeam, candidate selection.

### 4.2 Cleanup (`src/v2/cleanup.lua`)

**Purpose**: Hierarchical cleanup manager with tree structure.

**Key features**:
- `Add(resource)`: accepts Functions, RBXScriptConnections, Instances, or tables with `Destroy`. Tracks connections count on root.
- `Remove(key)`: disposes and removes by key.
- `Scope(key)`: creates a child cleanup scope; removing parent key discards old scope.
- `Destroy()`: disposes all entries idempotently; swaps first to allow cleanup callbacks to release sibling scopes.
- `ConnectionCount()`: returns total connections across tree.
- Idempotent `Destroy` calls; error in one callback doesn't prevent others from running.

**Test results** (core.spec.luau): 7/7 tests passed — idempotency, scope discard, error containment, connection counting.

### 4.3 Tracker (`src/v2/tracker.lua`)

**Purpose**: Player tracking with team detection and lifecycle management.

**Key features**:
- `sameTeam(a, b)`: Considers Neutral — returns `true` only if both are non‑Neutral and share the same Team. Neutrals never count as allies.
- `IsAlive(record)`: Checks character exists, descendant of Workspace, Humanoid health > 0, Root/Head exist in character.
- Property changed signals for Team, TeamColor, Neutral, DisplayName.
- Character lifecycle: `_add(player)`, `_character(record, character)`, `_clearCharacter(record)`, `_remove(player)`.
- ESP‑recursive guard: `onChild` checks for Humanoid or Head/HumanoidRootPart to prevent recursive overlay construction.
- Subscribe method for ESP/aim to react to tracker changes.

### 4.4 Aim (`src/v2/aim.lua`)

**Purpose**: Client‑side aim‑assist with FPS‑independent smoothing.

**Key features**:
- `alpha(speed, deltaTime)`: `1 - exp(-speed * deltaTime)` — FPS‑independent exponential smoothing. Verified at 30, 60, 144 FPS — all produce same remaining distance to target within 1e‑12.
- `screenDistance(x, y, z, onScreen, centerX, centerY, radius)`: Returns `nil` if off‑screen or z ≤ 0; otherwise checks if squared distance from center ≤ radius².
- Circle rendering: Optional `Drawing` API fallback; standard path uses `ScreenGui + Frame + UICorner + UIStroke`.
- Raycast wall check: `Params.FilterType = Exclude`, ignores local character and camera; rebuilds exclusion list each frame via `_updateFilter()`.
- Target candidate selection (`_candidate`): Validates target is alive, part exists in character, part is on‑screen and within FOV radius. No silent fallback — if Head absent, returns `nil`.
- Visible check (`_visible`): Raycast from camera through part; returns `true` if no obstruction or obstruction is descendant of target's character.
- Target lock (`_select`): If TargetLock enabled and existing target is valid, returns it; otherwise finds nearest valid candidate.
- Smooth movement (`_step`): `CFrame:Lerp(CFrame.lookAt(...), alpha(speed, deltaTime))`.
- Binding lifecycle: `_syncBinding()` binds to `RenderStep` at `Camera.Value + 1`, unbinds on state change. VR/Scriptable camera suspension. Text focus blocking. Window focus release.
- Input handling: RMB press/release, text focus blocking, menu open release.

**Test results** (core.spec.luau): 4/4 tests passed — FPS‑independence (30/60/144), screen distance, FOV inclusion/boundary, neutral team detection.

### 4.5 ESP (`src/v2/esp.lua`)

**Purpose**: ESP overlays with color modes, health/distance overlays, 10Hz heartbeat refresh.

**Key features**:
- Color modes: `Team / Relation` or `Custom`. `TeamColors` config flag controls whether player's TeamColor is used.
- `_color(record, component)`: If Custom → palette color; if TeamColors and not Neutral with Team → player's TeamColor.Color; otherwise teammate → FriendColor, enemy → EnemyColor.
- Overlay components: `Highlight` (AlwaysOnTop), `BoxHandleAdornment` (adorned to Root, CFrame + Size from GetBoundingBox), `BillboardGui` (Tag) with Name, Health, Distance lines.
- Heartbeat refresh: 10Hz (`self.Elapsed %= 0.1`). Only runs when `ESPEnabled` and there are active overlays. Invalidates when disabled or overlays empty.
- `_refresh(record)`: Eligibility check (ESPEnabled, not local player, alive, not teammate or ShowTeammates). Invalidation when character changes. Creates/reuses overlays via `_component()` which uses a scope per key for reuse.
- `_update(record, overlay, origin)`: Bounding box update, health/distance text lines.
- `_syncHeartbeat()`: Starts/stops heartbeat scope; on error, disables ESP and logs.

**Test results** (controllers.spec.luau): 7/7 tests passed — creation tardy de partes, 20 gerações de personagem com contagem estável, saída, morte/stream-out, nearest target, target lock, wall check and ESP color precedência.

### 4.6 UI (`src/v2/ui.lua`)

- Dragable header, Ctrl toggle (Left/Right Control), minimize button.
- 6 control types:
  - `AddToggle`: checkbox-style with knob animation.
  - `AddSlider`: horizontal slider with numeric display, step validation.
  - `AddButton`: action button with tweens.
  - `AddDropdown`: searchable/cyclable dropdown with keyboard navigation.
  - `AddColor`: hex textbox (#RRGGBB) with swatch preview.

- Reduced Motion support: `SetReducedMotion(value)` skips tweens when enabled.
- Scale handling: `SetScale(value)` clamps 0.75‑1.25, rescales layout.
- Open/close animation: CanvasGroup GroupTransparency tween (0.18s); visibility delayed for Reduced Motion.
- Keyboard navigation: Tab/Shift+Tab, focus management, slider arrow keys.

### 4.7 Main (`src/v2/main.lua`)

**Purpose**: App initialization, shutdown handshake, subsystem composition.

**Key features**:
- `shutdownPrevious(playerGui)`: Iterates `PlayerGui` children, finds owned previous instances (`VWMenuRuntime_v2` or `VWMenu_Client_v1`), invokes `VWMenu_Shutdown` BindableFunction. Asserts shutdown completes and instance is removed. This is the **previous instance cleanup race condition** — solved via shutdown handshake with BindableFunction + name/attribute verification.
- Creates root `ScreenGui` named `VWMenuRuntime_v2` with `ResetOnSpawn=false`, `IgnoreGuiInset=true`, attributes `Owner="VWMenu"`, `Version=2`.
- `BindableFunction` named `VWMenu_Shutdown` for cross‑instance handshake.
- Subsystem composition: `Config`, `Tracker`, `AimController`, `ESPController`, `UI`.
- Status line synchronization loop (every 0.5s when in SETTINGS tab).
- Returns `app` table with `:Destroy()` for complete cleanup.
